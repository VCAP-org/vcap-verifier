The same proof with every hash in the audit path replaced. The tree head signature still verifies — it is the log's, over a root the log really signed — and the leaf still names this key, so the only thing that fails is the walk from the leaf to the root, which is the whole point of an inclusion proof.

**Two labels, not one.** *key not in transparency log* is the §7 consequence: nothing here establishes the registration, so the ceiling drops to amber exactly as if the attachment were absent. *registry evidence invalid* is the fact a reader can act on — somebody handed this verifier a forged proof, which is a different thing from nobody having registered the key, and a verifier that reported only the first would throw away the part worth telling a user. The **core is untouched**: the capture is still signed by the key it says, and the outcome stays `authentic`.
