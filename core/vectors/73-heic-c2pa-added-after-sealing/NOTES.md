# 73-heic-c2pa-added-after-sealing

Vector 23 with a C2PA `uuid` manifest box inserted after `ftyp` — where C2PA 2.4 Annex A.5.3 puts the manifest store — **after** sealing. The mirror of vector 02: on a JPEG §4.1 excludes the JUMBF APP11 and the manifest may come and go; on ISO-BMFF nothing is excluded, the box is inside the canonical bytes, `media.hash` no longer matches and the photo is *tampered*.

This is the vector behind §4.1's "video embeds the manifest BEFORE sealing" and the same rule for HEIC. The asymmetry is not a preference: a C2PA `c2pa.hash.data` over a JPEG covers to end of file, so a manifest written before the trailer would be broken by the trailer, while a `c2pa.hash.bmff.v3` with `/free` excluded is not — so each container has exactly one order in which both bindings hold (`spec/c2pa-interop-1.0.md` §3).
