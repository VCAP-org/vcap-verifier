# Claiming conformance with a vcap-spec corpus

This file says what the sentence *"conformant with vcap-spec corpus 1.0.0"*
has to mean for a consumer to be able to check it, and how to produce the
report that backs it. `README.md` next to it describes the vectors themselves;
this one is about the claim.

## What the claim names

Three things, none of them optional:

| | Where it comes from | Why it is in the claim |
|---|---|---|
| **corpus version** | `vectors/VERSION` | names a release of the corpus, independent of `vcap/1.0` — the format version says what a proof looks like, the corpus version says what was checked |
| **manifest hash** | SHA-256 of `vectors/MANIFEST.json` as committed | names the *bytes*. A version can be claimed; a hash can be compared |
| **vectors run** | the runner's own count | a corpus version with no count is compatible with having run nothing |

## The rule that this whole file exists for

**A run of zero vectors is a failure, not a pass.**

The classic way a conformance suite goes green is by checking nothing: an
uninitialised submodule, a path that moved, a filter that stopped matching,
a test helper that returns an empty list and a `for` loop that therefore has
no body. Every assertion passes because none of them ran. A suite whose
corpus is missing must be **red**, and it must be red for that reason, in
those words.

Two corollaries, and they are what a reviewer should check in someone else's
runner:

- **Pin the count, do not floor it.** `expect(count).toBeGreaterThanOrEqual(30)`
  over a corpus of 84 hides the loss of 54 vectors. Compare against
  `vector_count` in `MANIFEST.json` and fail on inequality — that also catches
  the corpus that is newer than the runner, which is the useful half.
- **A vector you cannot run is declared, not dropped.** A runner that has no
  container demuxer, or no ASN.1, says so per vector in `not_run` with a
  reason. Silently narrowing the corpus and then reporting "all passed" is the
  same failure as running zero, at a smaller scale.

## The report

Shape: `schema/conformance-report.schema.json`. Worked example, regenerated by
CI on every push: `vectors/conformance-report.json` — this repository's own
reference verifier, measured against the corpus in the same commit.

```json
{
  "implementation": "acme-verify 3.2 (https://example.invalid/acme-verify)",
  "corpus_version": "1.0.0",
  "manifest_sha256": "…64 hex…",
  "vectors_declared": 84,
  "vectors_run": 84,
  "passed": 84,
  "failed": [],
  "not_run": []
}
```

A vector passes when the implementation produces the same `outcome`, `labels`,
`not_evaluated`, `core_hash`, `segments.verified` and, where the vector carries
them, `level`, `validated_at` and `location` as `expected.json`, and the same
`core_bytes_hex` for `jcs` vectors. Extra diagnostics a verdict carries are not
failures; the vector pins what it pins.

Check a report — yours or somebody else's — against the schema and the two
arithmetic rules the schema cannot express:

```
cd tools && npm ci
npm run validate -- --report path/to/conformance-report.json
```

## Running the corpus

```
cd tools && npm ci
npm test                      # every vector against the reference verifier
npm run conformance:report    # (re)writes vectors/conformance-report.json
npm run conformance:check     # exits 1 if the committed report is stale — CI runs this
```

An independent implementation runs the same loop with its own verifier over
the same directories: same inputs, same `expected.json`, no other oracle. The
loop is `tools/src/conformance.ts`, about a hundred lines, and it is meant to
be read and re-implemented rather than imported.

## What the claim does not mean

- **Not a security claim.** The corpus exercises the format: parsing,
  canonicalization, the signature chain, the absence labels, the §7 evidence
  levels. It does not measure key management, device integrity, or whether an
  implementation's UI says what its verdict means.
- **Not a watermark claim.** No vector in this corpus contains a watermark
  detector's answer, because no decoder lives in this repository
  (`README.md`, *the edge-case generator*). What the watermark is worth, where
  it holds and where it breaks, is measured separately and published in
  `spec/watermark-robustness-1.0.md`. Passing the corpus says nothing about it.
- **Not a claim about a newer corpus.** The corpus grows by addition, so
  passing 1.0.0 says nothing about 1.1.0's added vectors and everything about
  1.0.0's. State the version you ran.
