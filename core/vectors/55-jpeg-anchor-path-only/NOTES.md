# 55-jpeg-anchor-path-only

The offline half of §6.2's `anchor`: the audit path recomputes the batch root from `core_hash`, `index` and `tree_size`, with leaves `SHA-256(0x00 ‖ core_hash)` — deliberately the same tree as the transparency log, so a verifier carries one Merkle implementation and not two.

And it proves nothing yet. The root is still only the proof's word about itself until somebody reads what the contract recorded, so the label is *anchoring not verified* and the ceiling is amber — **never red**, because a verifier with no network has learned nothing bad. *not anchored* is gone, which is the label an absent attachment carries; the difference between "no anchor" and "an anchor I could not check" is the whole point of two labels.

Five leaves, ours third: an odd size, so the walk meets the incomplete level, and an odd position, so it meets a sibling on each side.
